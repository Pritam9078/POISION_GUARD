# Frontend integration map

Source inspected: `frontend/` (TanStack Start + **React/TypeScript**, Lovable-generated). Every page currently renders `src/lib/fixtures.ts`; only three calls hit the API (`/recipients/check`, `/approvals`, `/feedback`) and **each silently falls back to fixture data on failure**. That fallback must be removed when wiring — it shows fake results whenever the backend is down.

> ⚠️ Stack conflict: the PRD requires Vue 3 + JavaScript with no React/TS. The frontend as delivered violates that. This backend is framework-agnostic REST, so either a Vue rewrite or the current React app can consume it unchanged.

Response shapes deliberately mirror the fixture interfaces (`Scan`, `Finding`, `WatchedWallet`, `TrustedRecipient`, `Agent`, `SpendIntent`, `Policy`, `TeamMember`, `AuditEvent`, `SecurityEvent`, `Notification`, …) so the swap is mostly `FIXTURE → await api(path)`. Differences are listed per page.

Envelope: `{ success, data, meta: { requestId, page?, pageSize?, total? } }`; errors `{ success:false, error: { code, message, details? } }`. `src/lib/api.ts#api()` already unwraps `data` and throws `ApiError(code, message, status)` — keep it, delete the fallbacks.

Common states every page must handle: `401 UNAUTHENTICATED` → login; `403 FORBIDDEN` (role) → permission-denied state; `404` (also returned for other tenants' resources); `402 PLAN_LIMIT / PLAN_FEATURE` → upgrade prompt; `409 INVALID_STATE_TRANSITION` → refresh; `429 RATE_LIMITED`; `503 RPC_NOT_CONFIGURED / PROVIDER_UNAVAILABLE / FEATURE_DISABLED` → "intelligence unavailable" state.

## The React `/admin/*` routes inside `frontend/`

`frontend/src/routes/admin/*.tsx` duplicates the separate Vue `admin/` app. Admin must live on its own origin with its own session; delete these routes from the user app (they are also gated only by a localStorage demo session). Use `ADMIN_INTEGRATION_MAP.md` for the Vue admin.
